# Vendored Shared Facts (G12 / G8)

`shared-facts.json` is a byte-exact copy of `trueseal-sync`'s generated
`docs/shared-facts.json` — the one canonical source for the error, event,
status and Delivery Issue case names every SDK must expose (docs ADR-0003,
sync ADR-0028). The G12 parity gate compares this SDK's canonical `code`
strings against these lists: `scripts/check-parity.py`, wired into
`ci.yml`. Mirrors the Swift precedent (`trueseal-sync-swift/Parity/`).

## The pin (G8)

- **upstream**: `julianbonomini/trueseal-sync` @ `af16c4e7dbca21e5eaad4a816c2774b9cf8e4d7f`
  (`docs/shared-facts.json`, generated by `cargo run --bin gen-shared-facts`
  at that commit — never hand-edited upstream; the core's CI fails on drift).
- **sha256**: `159491b8a563c6928d564458c898e2c5e815e3e291091bc7e6342624031fe62a`
- The same hash is pinned in `ci.yml` (`SHARED_FACTS_SHA256`); the workflow
  verifies the vendored bytes before every comparison, so an accidental
  edit (or a silent upstream drift copied in) fails CI.

## Refreshing the pin

When the pinned core moves (a new candidate commit), refresh both the facts
and the hash together:

```sh
CORE_COMMIT=<full sha>
git -C ../trueseal-sync show "$CORE_COMMIT":docs/shared-facts.json > Parity/shared-facts.json
# then update the upstream commit above and SHARED_FACTS_SHA256 in
# .github/workflows/ci.yml to the new file's sha256, in the same commit.
```

A refresh that changes any list is a **parity event**: either the core grew
a case (the SDK must grow it too, in the same PR) or the SDK drifted (fix
the SDK). The check cannot be green with a stale facts file and a new core.

## What this check does not cover

`docs/api-surface.json` (the FFI function list) is pinned by construction —
the bindings come from the pinned core artifact, so the FFI surface cannot
drift from the core without the artifact changing. The behavioural half of
parity (what each case DOES) is covered by this repo's mapping tests
(`TrueSealErrorMappingTest`, `ModelMappingTest`) and by the cross-SDK
Interop Smoke in trueseal-e2e (G2).
